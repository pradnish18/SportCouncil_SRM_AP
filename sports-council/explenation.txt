### **1. REACT 18** ⚛️

#### **What is React? (Absolute Basics)**

Imagine you're building a website. Normally, you'd write HTML like this:

```html
<div>
  <h1>Clubs</h1>
  <button onclick="addClub()">Add Club</button>
  <ul id="clubList">
    <li>Basketball</li>
    <li>Football</li>
  </ul>
</div>
```

Then when data changes, you'd manually update the HTML:

```javascript
document.getElementById('clubList').innerHTML = '<li>Tennis</li>';
```

This is **tedious and error-prone** because you have to keep the JavaScript and HTML in sync manually.

**React solves this** by letting you write a **component** — a reusable piece of UI that automatically updates when data changes:

```javascript
function ClubList({ clubs }) {

      <h1>Clubs</h1>
      <button>Add Club</button>
      <ul>
        {clubs.map(club => <li key={club.id}>{club.name}</li>)}
      </ul>
    </div>
  );
}
```

**Key concept**: When `clubs` changes, React automatically re-renders the list. You don't manually update the DOM.

1. **Components** — Build reusable pieces (Navbar, ClubsGrid, EventsList)
2. **Efficiency** — Only updates parts that changed (fast)

### **2. VITE** ⚡

#### **What is Vite? (Absolute Basics)**

When you write React code, browsers can't understand it directly. They need plain JavaScript. So you need a **build tool** to convert React code → plain JavaScript.

Old build tools (like Webpack) were **slow**:
- Bundled everything at startup (took 10+ seconds)
- Every small change required rebuilding (slow feedback)

**Vite is a modern build tool that is FAST**:
- Serves files directly during development (instant startup)
- Only rebuilds what changed (instant feedback)
- Bundles for production (optimized)

#### **Why Your Project Uses Vite**

1. **Speed** — Developers get instant feedback while coding
2. **Simple setup** — Less configuration than Webpack
3. **ES modules** — Uses modern JavaScript standards

#### **Where Vite is Used in Your Project**

**Configuration**: `vite.config.js`
```javascript
export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:4000',  // Forwards /api calls to backend
      },
    },
  },
});
```

**What this does**:
- Tells Vite to run on port 3000
- When frontend calls `/api/clubs`, Vite forwards it to backend on port 4000
- This avoids "cross-origin" (CORS) issues during development

**When you run `npm run dev`**:
- Vite starts a dev server on `http://localhost:3000`
- Your browser loads the React app from there
- Changes instantly appear in browser

**When you run `npm run build`**:
- Vite bundles everything into optimized files
- Placed in `dist` folder
- These files are deployed to Netlify

### **4. SWR (Stale-While-Revalidate)** 📡

#### **What is SWR? (Absolute Basics)**

When your React component needs data from the backend, you need to:

1. Make an HTTP request
2. Wait for response
3. Show loading state
4. Handle errors
5. Update UI
6. Cache the data so you don't request twice

This is tedious to do manually. **SWR does all this automatically**.

**How it works**:
```javascript
import useSWR from 'swr';

function ClubsGrid() {
  const { data: clubs, error, isLoading } = useSWR('/api/clubs');
  
  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error loading clubs</div>;
  
  return <div>{clubs.map(club => <ClubCard club={club} />)}</div>;
}
```

**What SWR does**:
- Makes HTTP request to `/api/clubs`
- Returns `isLoading = true` while waiting
- Returns `data` once received
- Automatically caches results
- If you navigate away and back, it uses cached data
- Periodically re-fetches in background ("revalidate")

#### **Why Your Project Uses SWR**

1. **Less boilerplate** — No manual loading states
2. **Caching** — Smart data caching
3. **Real-time** — Auto-revalidates in background
4. **Error handling** — Built-in error states

#### **Where SWR is Used in Your Project**

**API helper**: `api.js`
```javascript
export async function fetcher(path) {
  const response = await fetch(`${API_BASE_URL}${path}`);
  if (!response.ok) throw new Error(`Request failed: ${response.status}`);
  return response.json();
}
```

This `fetcher` is used with SWR like:
```javascript
const { data: clubs } = useSWR('/api/clubs', fetcher);
```

**Example in components**: 
Most components use SWR to fetch data from backend APIs.

#### **What Happens if We Remove SWR?**

- You'd manually handle:
  - Loading states
  - Error states
  - Caching
  - Re-fetching
- Much more code in every component
- Higher chance of bugs

## **BACKEND TECHNOLOGIES**

### **7. NODE.JS & EXPRESS** 🚀

#### **What is Node.js? (Absolute Basics)**

JavaScript normally runs in **browsers**. Node.js lets JavaScript run on **servers**.

**Before Node.js**:
- Frontend code: JavaScript
- Backend code: Python, Java, PHP, C#, Ruby

**After Node.js**:
- Frontend code: JavaScript
- Backend code: JavaScript (same language!)

**Benefits**:
- One language for everything
- Share code between frontend and backend
- Huge ecosystem (npm packages)

#### **What is Express?**

Node.js is very low-level. **Express is a framework** that makes it easy to build APIs.

Without Express, creating an API endpoint is complex. **With Express**:

```javascript
const express = require('express');
const app = express();

app.get('/api/clubs', async (req, res) => {
  const clubs = await query('SELECT * FROM clubs');
  res.json(clubs);
});

app.listen(4000);
```

That's it! You have a working API endpoint.

#### **Why Your Project Uses Node.js + Express**

1. **JavaScript everywhere** — Same language for frontend and backend
2. **Fast development** — Express is simple and quick
3. **Non-blocking I/O** — Handles many requests simultaneously
4. **npm ecosystem** — Tons of packages available

#### **Where Node.js + Express Are Used**

**Entry point**: `server.js`
```javascript
const express = require('express');
const cors = require('cors');
const app = express();
const port = process.env.PORT || 4000;

app.use(cors());           // Allow frontend to call backend
app.use(express.json());   // Parse JSON requests

app.use('/api/clubs', clubsRouter);
app.use('/api/events', eventsRouter);
// ... more routes

app.listen(port, () => {
  console.log(`Backend server running on http://localhost:${port}`);
});
```

**What this does**:
- Creates Express app
- Enables CORS (allows requests from frontend)
- Enables JSON parsing (read POST body)
- Registers all route handlers
- Starts server on port 4000

#### **What Happens if We Remove Node.js + Express?**

- Would need to rewrite backend in Python, Java, Go, etc.
- Can't share code with frontend
- Completely different development

### **8. POSTGRESQL** 🗄️

#### **What is PostgreSQL? (Absolute Basics)**

You need somewhere to **store data permanently** (clubs, events, users, etc.).

**File system** — Bad choice
- Can't query efficiently
- No relationships between data
- Not suitable for concurrent access

**SQL Database** — Good choice
- Query data efficiently
- Support relationships
- Transactions (all-or-nothing operations)
- Millions of records efficiently

**PostgreSQL is an open-source SQL database**. It's:
- Powerful (supports JSON, arrays, full-text search)
- Reliable (ACID transactions)
- Free

#### **Database vs. API vs. Frontend**

Think of three layers:
- **Frontend** — User interface (what users see)
- **Backend/API** — Business logic (processes requests)
- **Database** — Data storage (where everything is saved)

Frontend never talks to database directly. It goes through backend:

```
Frontend Request → Backend → Database → Backend Response → Frontend
```

#### **Why Your Project Uses PostgreSQL**

1. **Structured data** — Clubs, events, achievements fit well in tables
2. **Relationships** — A club "has many" events
3. **Queries** — Find all events in "Basketball" sport easily
4. **Advanced features** — pgvector for AI chatbot

#### **Where PostgreSQL Is Used in Your Project**

**Schema**: `schema.sql`
```sql
CREATE TABLE IF NOT EXISTS clubs (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,

  logo_url TEXT NOT NULL,
  -- ... more fields
);

CREATE TABLE IF NOT EXISTS events (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  club_id TEXT NOT NULL,  -- Link to clubs table
  -- ... more fields
);
```

**Connection**: `pg.js`
```javascript
const pool = new Pool({
  connectionString: process.env.DATABASE_URL
});
```

**Usage in routes**: `index.js`
```javascript
const clubs = await query('SELECT * FROM clubs ORDER BY "order" ASC');
res.json(clubs);
```

#### **Database Schema (Your Tables)**

| Table | Purpose |
|-------|---------|
| `clubs` | Sports teams (Basketball, Football, etc.) |

### **9. BCRYPT** 🔐

#### **What is Bcrypt? (Absolute Basics)**

When users sign up with a password, you can't store it as plain text:

```javascript
// ❌ WRONG - Never do this!
const users = {
  'john@example.com': 'password123'  // Exposed!
};
```

If your database is hacked, passwords are stolen.

**Bcrypt solves this** by **hashing** the password:

```javascript
import bcrypt from 'bcrypt';

// When user signs up:
const hashedPassword = await bcrypt.hash('password123', 10);
// Store: hashedPassword = '$2b$10$...(random gibberish)...'

// When user logs in:
const isCorrect = await bcrypt.compare('password123', storedHash);
// Returns: true or false (without revealing stored hash)
```

**Key properties**:
- One-way (can't reverse hash to get password)
- Slow (intentionally, to resist brute force)
- Unique (same password hashed twice looks different)

#### **Why Your Project Uses Bcrypt**

1. **Security** — Passwords are encrypted, not stored as plain text
2. **Standards** — Industry-standard for password hashing

#### **Where Bcrypt is Used**

`index.js` (likely uses bcrypt)
- When admin enters password, bcrypt compares it to stored hash
- If match, login succeeds

#### **What Happens if We Remove Bcrypt?**

- Store passwords as plain text (HUGE security risk)
- Anyone with database access sees all passwords
- Legal liability if hacked

### **10. OLLAMA + pgvector** 🤖

#### **What is Ollama? (Absolute Basics)**

Normally, to use AI, you'd call a cloud service:

```javascript
const response = await fetch('https://api.openai.com/v1/chat/completions', {
  method: 'POST',
  body: JSON.stringify({ prompt: 'What is a basketball club?' })
});
```

**Problems**:
- Costs money per request
- Sends your data to third party
- Requires internet
- Rate limited

**Ollama is an open-source AI engine you run locally**:

```javascript
const response = await fetch('http://localhost:11434/api/generate', {
  method: 'POST',
  body: JSON.stringify({ 
    model: 'deepseek-r1:1.5b',
    prompt: 'What is a basketball club?'
  })
});
```

**Benefits**:
- Free (no API costs)
- Private (no data sent anywhere)
- Works offline
- Instant (runs on your server)

#### **What is pgvector?**

Ollama alone can answer questions, but it doesn't know about YOUR sports council (clubs, events, etc.).

**pgvector** solves this with **Retrieval-Augmented Generation (RAG)**:

1. Take club information ("Basketball club has 20 members...")
2. Convert to numbers (embeddings) using AI
3. Store in PostgreSQL with pgvector
4. When user asks question, find similar information
5. Pass that information to AI along with question
6. AI answers using your data

**Example flow**:

```
User: "What sports clubs exist?"
  ↓
Backend finds similar information using pgvector
  ↓ Retrieves: "Basketball club has 20 members. Football club has 30 members."
  ↓
Passes to Ollama: "Based on: Basketball club... Football club... Answer: What sports clubs exist?"
  ↓
Ollama: "The sports council has Basketball and Football clubs."
```

#### **Why Your Project Uses Ollama + pgvector**

1. **No API costs** — Runs locally
2. **Privacy** — No external API calls
3. **Customized** — Answers based on your sports council data
4. **Always available** — Works offline

#### **Where Ollama + pgvector Are Used**

**AI Engine**: `rag.js`
```javascript
const OLLAMA_HOST = process.env.OLLAMA_HOST || 'http://127.0.0.1:11434';
const EMBED_MODEL = 'nomic-embed-text';  // Converts text to numbers
const GEN_MODEL = 'deepseek-r1:1.5b';    // Generates answers

async function generateEmbedding(text) {
  const res = await fetch(`${OLLAMA_HOST}/api/embeddings`, {
    method: 'POST',
    body: JSON.stringify({ model: EMBED_MODEL, prompt: text })
  });
  return data.embedding;  // Returns array of numbers
}

async function generateAnswer(context, question, history) {
  const prompt = `You are a helpful assistant for the SRM Sports Council website. 
Answer the question based ONLY on the provided context. 

Context:
${context}

Question: ${question}`;

  const res = await fetch(`${OLLAMA_HOST}/api/generate`, {
    method: 'POST',
    body: JSON.stringify({ model: GEN_MODEL, prompt, stream: false })
  });
  return data.response;  // AI-generated answer
}
```

**Chatbot endpoint**: `index.js`
- User sends question
- Backend retrieves relevant club/event information using pgvector
- Passes to `generateAnswer()` with context
- Returns AI-generated response

**Vector table**: `schema-rag.sql`
- Stores embeddings (numerical representations of text)
- Enables semantic search (find similar information)

#### **What Happens if We Remove Ollama?**

- No chatbot feature
- Users can't ask questions about sports council
- Would need to remove AI functionality or use cloud service
